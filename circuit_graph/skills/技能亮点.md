# 技能亮点 —— 嵌入式开发 Claude Code Skill 集

> 演示用文档。一句话定位:**把嵌入式开发中"查 datasheet、对网表、写固件、编译烧录、看串口、抓波形"这条全链路的手工活,变成对 Claude Code 说一句话。**

本目录共 13 个 skill,覆盖 5 个工作流:

| 工作流 | 技能 |
|---|---|
| 调试/抓数据 | `serial-monitor`、`atk-logic-capture` |
| Keil 工程 | `keil-init`、`keil-batch-gen` |
| GCC 编译烧录 | `mm32-armgcc-build` |
| 硬件资料解析 | `pdf-pin-extract`、`pdf-table-reader`、`pin2json`、`netlist-signalmap`、`schmd-from-netlist` |
| 硬件分析/审查 | `hardware-diff-by-codes`、`cg`、`kicad` |

## 一、手工是怎么做的(痛点现场)

### 1. 查芯片引脚:打开 200 页 PDF,人肉抄表

拿到一颗新 MCU(比如 MM32G0001),要配 GPIO 就得:

1. 打开 datasheet PDF,翻到 "Pin Assignment" 章节;
2. 引脚定义表、复用功能(AF)表通常**跨 3~5 页**,每页重复表头;
3. 人肉抄到 Excel / 记事本,一个 20 脚的芯片抄完核对完要 **30 分钟~1 小时**,还容易抄错行;
4. 抄出来的是"给人看的表",**不是机器可读的数据**,后面每一步(配 GPIO、对网表)都要重新翻 PDF。

### 2. 对网表:文本编辑器里大海捞针

想知道"PA1 这个脚在板子上实际接的是什么",手工流程:

1. 从 Altium/DXP 导出 `.NET` 网表;
2. 用记事本/VS Code 打开,网表是纯文本的方括号+圆括号格式,几千行;
3. 搜 `(1` 找到 1 号脚挂的网络 `NetR5_1`,再搜 `NetR5_1` 看它连到哪,发现连了个电阻 R5;
4. 再追 R5 另一头的网络…… **一条链追 3~4 跳,一个 20 脚的 MCU 追完半天没了**;
5. 追完还要和固件源码里的 `#define KEY1 GPIOA->IDR.P1` 对一遍,才能闭环。

### 3. 判断"这两份固件是不是同一块板子"

老项目维护最常见的场景:拿到两份固件,没有原理图,要判断硬件是否一致。手工做法是**逐行读两份代码的全部 GPIO 初始化**,在脑子里模拟寄存器值,再逐脚对比——一个下午起步,且极易漏掉 `#ifdef` 分支。

### 4. Keil 编译烧录:被 GUI 绑架

1. 双击打开 Keil µVision,等 GUI 加载;
2. 点 Build,**编译输出只在 GUI 窗口里**;
3. 点 Download,等进度条;
4. 想自动化?UV4.exe 有命令行 `-b` 参数,但**退出码不可靠**(编译失败也返回 0),**输出不流到 stdout**,只能解析它吐出的 log 文件才知道成败——这是官方工具链公开的限制。

### 5. 抓波形:逻辑分析仪软件的"人工三件套"

用 ATK-Logic 抓 UART 波形,手工流程:

1. 打开官方 GUI,手动设置采样率、通道、触发;
2. 手动点"开始",复现现象,手动点"停止";
3. 手动 Ctrl+S 弹出保存对话框,**手填文件名**;
4. 在 GUI 里目测波形、手量脉宽——想解码 UART 还要在 GUI 里加解码器再点一遍。

**全程无法脚本化**:官方软件没有 CLI、没有 API、没有插件 SDK。

### 6. 看串口:每次开 PuTTY 配一遍

板子插上 CH340,要开 PuTTY/SecureCRT,选 COM 口、填 115200、点 Open;想发个测试按键指令再手敲。每天都做的事,每次都重来一遍。

## 二、现有工具的现状(为什么不够用)

### PDF 表格提取:没有主流工具支持跨页合并

| 工具 | 现状 |
|---|---|
| **Camelot** | 画线表格提取得好,但[官方 issue #278 明确:跨页表格按页拆开,需手工合并](https://github.com/atlanhq/camelot/issues/278);**仓库 2025 年 1 月已归档停更**;依赖 Ghostscript |
| **Tabula** | 依赖 Java;GUI 需手动框选表格;跨页表格同样按页拆 |
| **pdfplumber** | 数字 PDF 精度好、维护活跃,但合并单元格、跨页表都要自己调 `table_settings` 再写后处理 |

学术界把 "page-break 导致的表格断裂" 列为 PDF 表格提取的[六大典型失败模式之一](https://www.semantic-web-journal.net/system/files/swj3184.pdf)。**结论:主流开源工具全部按页独立处理,跨页合并没有现成方案,只能每家自己写拼接逻辑。**(参考:[Tabula vs Camelot vs pdfplumber 2026 对比](https://dev.to/martin_pdfexcel/tabula-vs-camelot-vs-pdfplumber-in-2026-which-python-library-actually-wins-22kn))

### 逻辑分析仪:能脚本化的买不起,买得起的不能脚本化

| 方案 | 脚本能力 | 代价 |
|---|---|---|
| **Saleae Logic 2** | 官方 Python Automation API,很完善 | 硬件**几百到几千美元**([定价](https://gsasindia.com/blog/saleae-logic-india-pricing-buyers-guide-2026)) |
| **sigrok / PulseView** | `sigrok-cli` + Python 绑定,开源免费,258+ 设备 | 需买兼容硬件(FX2 克隆 ~10 美元但仅 24MS/s);**不支持 ATK-Logic 的 .atkdl 格式** |
| **ATK-Logic 官方软件**(正点原子) | **无 CLI、无 API、无插件 SDK**,GUI 独占 | 硬件便宜,但自动化能力为零 |

([sigrok 生态](https://learn.sparkfun.com/tutorials/using-the-usb-logic-analyzer-with-sigrok-pulseview/all?print)、[Saleae 自动化](https://gsasindia.com/products/saleae/saleae-logic-mso-2x100))

### 串口工具:GUI 工具自动化弱,脚本工具要自己写

[PuTTY 基本没有自动化能力](https://softpanorama.org/Utilities/teraterm.shtml);TeraTerm 有 TTL 宏语言但生态老;pyserial 完全可编程但**每次都要自己写脚本**。([Serial Studio 对比文档](https://serial-studio.com/help/comparison))

### Keil 自动化:官方 CLI 是"半成品"

UV4.exe 只有 `-b/-r/-c/-o` 几个参数,**不往 stdout 写编译输出**,必须轮询 `-o` 指定的 log 文件;[部分错误只弹 GUI 对话框,直接卡死自动化](https://forum.sublimetext.com/t/a-custom-sublime-build-around-keil-uvision4-compiler-ide/35683);退出码不可信。要真正的 CI 得迁移到 csolution/armgcc 工具链。

### 网表/硬件对比:根本没有现成工具

"从 .NET 网表反推每个引脚的板上信号名"、"对比两份固件判断是否同一块 PCB"——这两件事**不存在任何现成工具**,此前纯靠人肉。

## 三、亮点:每个技能解决了什么

### 🌟 亮点 1:PDF → 结构化引脚数据,5 分钟替代 1 小时(`pdf-pin-extract`)

- ** pipeline**:pypdfium2 关键词定位页(中英双语关键词)→ camelot-py 2.x(lattice 优先, stream 兜底)提表 → pandas 清洗 → 对齐输出 JSON;
- **解决跨页表头重复、soft hyphen、零宽字符、合并单元格**这些 datasheet 特有的脏数据;
- 自带**交叉校验** `verify_output.py`:引脚必须出现在对应 port 的 AF 表里,机器自检而不是人眼核对;
- camelot-py 2.x 基于 playa-pdf,**摆脱 Java/Ghostscript 依赖**;
- 产出物是**机器可读 JSON**,直接喂给下游的网表映射技能——这就是"5 分钟拿到引脚表"的含义。

### 🌟 亮点 2:任意 PDF 表格一键全提,跨页自动合并(`pdf-table-reader`)

- 直击上面"主流工具全部不支持跨页合并"的行业空白:**按首行归一化(忽略空白/大小写/标点)比较相邻页的表,自动拼接**,并在输出里标注"此表跨 N 页合并";
- 一个 PDF → 一个 markdown 文件,每张表带页码/标题/accuracy 元信息;
- 依赖缺失时清晰报错附安装命令,不静默失败;
- 已知缺陷也写进文档(连续同构寄存器表可能误判合并)——诚实比吹牛重要。

### 🌟 亮点 3:无注入驱动官方 GUI,让"不能脚本化"的逻辑分析仪可脚本化(`atk-logic-capture`)

这是最硬核的一个。ATK-Logic 官方软件没有任何自动化接口,技能的解法:

- 用 **C# 写了一个 12.5KB 的 `atk_bg.exe`**,通过 Win32 `PostMessage/SendMessage` 向官方 Qt GUI 发消息(模拟按 F1 开始、F2 停止、给 Save-As 对话框填路径)——**不抢前台焦点、不用 keybd_event/SendInput 注入**,官方软件零修改;
- 淘汰了旧方案(代理 Qt5Network.dll + TCP server),从"hack 二进制"降级为"窗口消息",稳得多;
- 自己写了 **.atkdl 二进制格式解析器**(`capture_reader.py`)——官方没公开格式,逆向出来的;
- 自动分类信号(UART/PWM/SPI/I2C/时钟)并分发到对应协议解码器;
- 全程踩坑 14 条写进 SKILL.md(GUI 会覆写 set.ini 需置只读、taskkill 会留恢复弹窗、快捷键必须单键……)——**这些坑下次永不重踩**。

对比:要实现同样的自动化,Saleae 方案要花几百美元买硬件;这个技能让你**手里几十块的国产分析仪获得同等的 CI 级自动化能力**。

### 🌟 亮点 4:网表 → 板上信号名,全自动六级降级(`netlist-signalmap` / `schmd-from-netlist`)

- 把"文本编辑器里追网络"变成一条命令,输出 Markdown 表:`引脚号 | 芯片功能 | 板上信号名 | 依据`;
- **六级命名优先级自动降级**:具名网络 → 带名测试点 → 芯片 JSON 补电源脚 → 串接 R/L 追溯相邻具名网络(只穿 R/L 不穿 C,只追一跳)→ 源码宏 → 留 ⚠ 给人;
- `schmd-from-netlist` 更进一步:**扫描固件源码里的 GPIO 宏做"源码闭环"**——固件里的 `#define` 名字直接成为板上信号名;
- 对实在定不下来的脚,脚本导出 **2 跳 BFS 拓扑指纹**,交给 LLM 解读"疑似功能+置信度"——**脚本干确定的事,LLM 干模糊的事**,边界清晰;
- 实测能逐字还原设计者的命名。

### 🌟 亮点 5:GPIO 寄存器级模拟,固件反推硬件(`hardware-diff-by-codes`)

- 纯方法论 skill:教 LLM **从复位态按执行顺序模拟 GPIO 寄存器(CRL/CRH/AFRL/ODR/BSRR)的最终值**,逐 pin 对比两份固件;
- 核心洞察一句话:**"同一块 PCB ⟺ 所有外设初始化后 GPIO 寄存器最终值相同"**;
- AF 编号变了 = 硬件差异;只有模式变了 = 固件差异;"永不信注释,hex 值是唯一真相";
- 快速路径:90% 引脚在 GPIO_init 后不再变化,只复查后续 init 触及的子集;
- 输出四类结论:同 PCB / 选配未焊 / 不同 PCB / 需人工——**不确定就明说,不硬答**。

### 🌟 亮点 6:驯服 Keil CLI(`keil-init` / `keil-batch-gen`)

- 针对"UV4 退出码不可靠、输出不进 stdout"的官方缺陷:脚本**解析 build.log 的 "N Error(s)"、download.log 的 "Verify OK"** 判断成败,并比对 .axf 与源文件时间戳防陈旧构建;
- 一条命令在 `.uvprojx` 旁生成 `__build.ps1` / `__download.ps1`,此后编译烧录全是 `0 Error, 0 Warning` 的确定性判定;
- `keil-init` 还顺手生成 CLAUDE.md(**逻辑禁区声明**:哪些目录 AI 不许碰)+ **pre-commit 钩子**(暂存文件命中禁区正则直接拦截)——把"框架文件别乱改"从口头约定变成强制约束。

### 🌟 亮点 7:MM32 纯命令行编译烧录(`mm32-armgcc-build`)

- xpack arm-none-eabi-gcc 直编(QP-nano 源码清单、CFLAGS/LDFLAGS 全显式)+ objcopy 出 hex/bin + size 报告;
- pyOCD + MindMotion DFP pack 烧录,全程无 GUI;
- 踩坑记录即价值:pyOCD 烧完芯片停在 halt 必须 `reset; continue`;2KB RAM 的 SP 必须是 0x20000800,错了 push/pop **静默失败**。

### 🌟 亮点 8:串口一句话搞定(`serial-monitor`)

- pyserial 单脚本,**自动识别 CH340**,默认 115200,日志落盘;
- `--send k1~k4` 预置按键指令——配合 E2E 测试,Claude 可以自己"按按键"验证固件行为;
- 从"开 PuTTY 配一遍"到"说一句话"。

### 🌟 亮点 9:电路图问答与 KiCad 审查(`cg` / `kicad`)

- `cg`:对 .NET/.kicad_sch 建图,"R100 是什么""I2C 总线上挂了谁""电源链怎么走"直接问,告别文本搜网表;
- `kicad`:原理图/PCB/Gerber 全量审查,DRC/ERC/DFM/BOM/电源树,每条发现带**置信度标签**和 trust_summary 汇总;强制纪律——"一致性 ≠ 物理正确",必须回到原始 .kicad_sch 交叉验证。

## 四、这套东西的整体设计哲学

1. **单职责、可串联**:每个 skill 只做一件事,但输出全是结构化 JSON/Markdown,天然组成流水线:`pdf-pin-extract`(芯片 JSON)→ `netlist-signalmap`(网表+JSON=信号表)→ `schmd-from-netlist`(+源码闭环)→ 写固件 → `keil-batch-gen`(编译烧录)→ `serial-monitor`/`atk-logic-capture`(验证);
2. **本地优先**:全部本机运行,不依赖云 API;
3. **确定性的事给脚本,模糊的事给 LLM**:拓扑提取是脚本,拓扑解读是 LLM;寄存器模拟是规则,结论判定有"需人工"这个诚实选项;
4. **踩坑即文档**:14 条 atk 坑、pyOCD halt 坑、SP 地址坑全部写进 SKILL.md,**知识沉淀在流程里,不依赖个人记忆**;
5. **禁区即代码**:CLAUDE.md 声明 + pre-commit 钩子强制,AI 协作的边界是硬约束。
